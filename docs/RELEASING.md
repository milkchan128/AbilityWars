# 버전 및 릴리스 규칙

이 포크의 정식 릴리스 버전은 원본 AbilityWar 버전 및 Minecraft 버전과 별도로 `1.0.0`부터 시작합니다. 정식 배포 버전의 기준은 `build.gradle.kts`의 `version`이며 Git 태그는 `v1.0.0` 형식을 사용합니다.

## 버전 증가

| 변경 종류 | 증가 방법 | 예시 |
| --- | --- | --- |
| 버그 수정, 호환 보완, 문서·배포 수정 | 마지막 숫자를 1 올립니다. | `1.0.0` → `1.0.1` |
| 기존 사용법을 유지하는 기능 추가 | 가운데 숫자를 1 올리고 마지막 숫자를 0으로 맞춥니다. | `1.0.1` → `1.1.0` |
| 기존 API·설정·사용법의 호환성이 깨지는 변경 | 첫 숫자를 1 올리고 나머지를 0으로 맞춥니다. | `1.1.0` → `2.0.0` |

일반 수정 릴리스는 패치 버전만 올립니다. 발행된 버전과 태그는 덮어쓰지 않고 수정 사항은 다음 버전으로 배포합니다.

## 발행 순서

1. `build.gradle.kts`의 버전과 README의 배포 파일명을 함께 변경합니다.
2. `CHANGELOG.md` 맨 위에 패치 노트를 추가하고 `docs/releases/v<버전>.md`에 지원 환경, 설치 방법, 검증 범위 및 주의사항을 작성합니다. 날짜는 KST 기준입니다.
3. JDK 21 환경에서 `.\gradlew.bat clean build`를 실행합니다. 새 동작이나 호환 코드 변경이 있다면 격리된 테스트 서버에서 필요한 검증을 추가합니다.
4. 배포 JAR 내부의 `plugin.yml` 버전, `api-version`, Mojang 매핑 선언 및 필요한 클래스·의존성을 확인하고 SHA-256을 생성합니다.
5. 변경사항을 검토·커밋하고 해당 커밋에 버전 태그를 붙입니다. 릴리스 발행 요청이 있을 때 커밋과 태그를 원격 저장소에 올립니다.
6. GitHub에 초안 릴리스를 생성하고 배포 JAR와 `SHA256SUMS.txt`를 첨부합니다. 서버 지원 범위가 문서 및 실제 파일과 일치하는지 확인한 뒤 정식 발행합니다.
7. 업로드된 파일을 다시 내려받아 SHA-256, 태그가 가리키는 커밋 및 릴리스 공개 상태를 확인합니다.

배포 파일은 `build/libs/AbilityWar-<버전>.jar`입니다. `-plain.jar`, 검증용 `AbilityWar-PaperSmoke.jar`, 서버 파일 및 로컬 테스트 설정은 릴리스에 첨부하지 않습니다.

`1.1.0`부터 자동 업데이트가 정식 릴리스의 `AbilityWar-<버전>.jar`와 `SHA256SUMS.txt`를 이름으로 찾습니다. 태그와 JAR 내부 버전을 맞추고, 위 두 파일을 첨부한 초안을 검증한 뒤 정식 발행하세요. 다른 서버 버전으로 지원 범위를 바꾼 JAR는 기존 1.21.11 서버의 자동 업데이트에서 거부됩니다.
